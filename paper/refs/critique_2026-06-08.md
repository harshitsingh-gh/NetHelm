# Holistic Critique — NetHELM blast-radius benchmark (2026-06-08)

> Convened red-team-critic + noc-veteran + research-standards-reviewer for a SYSTEMIC
> critique of the whole benchmark (not per-scenario). They converged. Verdict, blunt:
> **the infrastructure is sound and the idea is genuinely novel, but this is NOT a
> paper yet — it is a grading harness with an untested hypothesis.** Every finding
> below was reproduced from the repo by the agents.

## The one-sentence reviewer rejection (today, and it sticks)
"No real-model evidence beyond three single-shot calls on non-trap scenarios; the
'8-dimensional' grader reduces to a 1–2 dimension binary per scenario; the 11
scenarios collapse to ~6 mechanisms (4 are siblings of one outbound-filter trap);
ground truth is Batfish on 3–5-node toys with admitted modeling gaps and an unpinned
`:latest` image; the central 'trap' failure mode is measured by a flag never enabled
in the pipeline; and several prompts leak the answer."

## Convergent findings (all three agents)

### EXISTENTIAL
1. **No experiments.** Only n=1 Claude-Haiku on 3 non-trap scenarios. The thesis
   ("LLMs fail at multi-dimensional blast radius") is currently unsupported. **This
   is the gap; everything else is polish on a benchmark with no results.**
2. **The trap metric is dead code.** `is_trap`/`false_alarm` exist in the grader but
   `Scenario` has no `is_trap` field and the runner never sets it → the headline
   failure mode (models predict session loss on attribute changes) is structurally
   unmeasured. A model predicting ∅ on a trap scores macro_f1=1.0.
3. **No baselines.** Only the empty/recall-floor baseline exists. Need a
   **naive-session-loss (D1) baseline** and a naive-count baseline — without them
   "LLMs fail at traps" is unfalsifiable.

### GRADING / ORACLE INTEGRITY
4. **"8-D" is effectively 1–2 dims/scenario** → macro_f1 ∈ {0, 0.5, 1.0}, a binary.
   The 0.80 pass threshold is a magic number. → report per-dimension P/R
   distributions, not pass@0.80.
5. **Ground truth is unpinned.** Batfish runs as `:latest` (mutable); tag drifts
   across docs (`:netbrace`/`:nethelm`/`:latest`). No determinism gate on
   `ExtendedOracle.compute` (only the v0 path has one); evidence is 2–5×, not the
   doctrine's ≥10×. Only ONE live-emulator cross-check (ipc3). batfish venv was
   missing pydantic.
6. **Oracle scores ungroundable dimensions.** D6 `filter_deltas` is a schema column
   the oracle never computes. D3 `_flow_outcome` is ECMP-blind (any-trace-delivers)
   → silently wrong for future partial-loss scenarios.

### SCOPE / DIVERSITY
7. **~6–7 mechanisms, not 11.** The ipc family = 1 mechanism / 4–5 files (36% of the
   suite). No real generators (only `ipc_fanout` cardinality variant; `generator.py`
   is the v0 path and does not feed the 11). "150–220 instances × 14–16 classes" is
   aspirational. → report MECHANISMS not files; build real generators.
8. **Coverage skew:** dense where Batfish is easy (RIB/FIB policy diffs), EMPTY where
   the highest-MTTR real outages live — **mgmt-plane lockout, RR best-path hiding,
   anycast catchment** (KB now written for all three, zero built).

### PROMPT HYGIENE (recurring — third independent discovery)
9. **3 of 11 prompts still leak the answer:**
   - `leak_ms` — "backed by a **blackhole** static… no real path" (leaks D7 kind).
   - `ipc_static` — "the advertisement is **withdrawn/lost**… reachability intact"
     (gives away the entire D9-fires/D2-D3-silent GT).
   - `waypoint` — "**Reroute** src→dst off `way`" (states the D4 outcome).
   No automated guard. → fix all 3 + add a CI lint test (regex over
   description+intents for outcome words / dimension-name tokens).

### POSITIONING (publication)
10. **Novelty overclaim.** NetPress/NetArena (arXiv:2506.03231) HAS a "safety" axis
    (binary rule-adherence). "Batfish already does change-validation." → reframe:
    **typed-set blast-radius prediction from static configs WITHOUT tool access**;
    Batfish is the *oracle*, not a competitor. (Defensible novelty sentence + the
    "Batfish already does this" rebuttal are in the standards-reviewer output.)
11. **κ is the wrong instrument for oracle determinism** (Batfish is deterministic,
    not human-labeled) — saying so is a strength. κ DOES apply to **independent-expert
    validation of oracle correctness** on a 50–100-instance subset (human ≠ author,
    ≠ fleet model). Plus oracle-vs-emulator agreement at scale (≥20 instances) and
    ≥10× determinism tables.

### Specific go/no-go
- **`ipc_static`:** surface D9 (`bgp_withdrawn`) in `reporting/` + the metric table,
  or KILL it — a scored dimension that never appears in output is dead weight.
- **`ecmp`:** demote to a trivial sanity anchor; don't count it as a mechanism.

## Prioritized plan (synthesis of all three)

**A. Cheap + critical (do before any more scenarios):**
1. Fix the 3 prompt leaks + add a CI prompt-hygiene lint test.
2. Wire `is_trap` end-to-end + add the naive-session-loss and naive-count baselines
   to the runner.
3. Pin ONE Batfish image digest everywhere; add pydantic+SDKs to the batfish venv;
   add the ≥10× determinism gate to `ExtendedOracle.compute`; reconcile tag drift.
4. Stop showing dimensions the oracle can't ground (D6: build it w/ cEOS or remove
   from schema/prompt; fix or document D3 ECMP-blindness).
5. `ipc_static` D9-in-reporting go/no-go.

**B. Coverage (fix the skew — NEW mechanisms, not ipc variants):**
6. Build **mgmt-plane lockout** (cheapest, 4 post-mortems, inverted reasoning),
   then **RR best-path hiding**, then **anycast catchment** (KB ready for all three).
   Takes honest mechanism count 6→9.

**C. Scale + science (the actual paper):**
7. Build real parameterized generators for the 3–4 thesis classes → ≥150 instances
   (this is also contamination control: randomize numbering).
8. Oracle-validity package: ≥20-instance Batfish-vs-FRR agreement, ≥10× determinism
   table, 50–100-instance independent-expert validation (κ-adjacent). **Needs an
   independent human — line up now.**
9. THEN the $1000 fleet sweep: ≥5–6 models × ≥150 instances × N≥5, mean±CI,
   per-dimension breakdown, trap false-alarm rate, significance vs baselines.
10. Reframe the contribution sentence (typed-set prediction; NetPress + Batfish
    distinctions) before writing any paper text.

## Bottom line
The build phase produced sound infrastructure and a real, defensible idea. But the
project has been optimizing breadth (more scenarios) when the binding constraint is
**science** (baselines + is_trap + generators-for-scale + a validity study + the
sweep). Re-prioritize from "author scenario #12" to plan A→B→C above. The novelty is
genuine; the gap between claimed and measured is the whole job now.
